# 저작권·판매 관련 검토

검토 기준: 2026-10-11 확인한 저장소와 설치 패키지 메타데이터, 아래 공식 자료. 기술적·일반적 쟁점 점검이며 변호사의 법률 의견이나 무침해 보증이 아닙니다. 실제 사업 형태·배포 방식·판매 국가·최신 법령에 따라 달라집니다.

## 결론

현재 파일 목록에서 출처 불명 이미지/폰트/상용 템플릿을 새로 도입하지 않았습니다. 기존 Lucide/Feather 고지와 런타임 의존성의 라이선스 원문을 보존했습니다. 그러나 '아무 법적 문제 없이 즉시 판매 가능'이라는 결론은 내릴 수 없습니다. 특히 원본 프로젝트 라이선스 결정, LGPL/MPL 재배포 조건, 개인정보 위탁, 결제 사업자 자격은 미완료 출시 조건입니다.

## 원본 코드와 공개 저장소

검사 시 프로젝트 전체에 적용되는 루트 LICENSE가 없었습니다. 공개 저장소 자체가 오픈소스 사용·재판매 허락을 의미하지 않으며, GitHub 플랫폼의 보기/fork 권리와 일반 재배포 허락도 구분해야 합니다. 사용자 대신 MIT/Apache/독점 라이선스를 임의 적용하지 않았습니다. 원본 작성자·공동 기여자·수업/직장/외주 계약상 권리와 사용한 외부 코드의 출처를 확인하고 라이선스를 결정하세요. 코드 유사성/특허/전 세계 상표 검색까지 수행한 것은 아닙니다. [GitHub 라이선스 안내](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/licensing-a-repository)

## 확인한 외부 구성요소

`DEPENDENCIES.json`은 실제 런타임 패키지 31개의 버전/라이선스 메타데이터/고지 파일 SHA-256입니다. `SBOM.cdx.json`은 CycloneDX 목록이며 `third_party`는 wheel에 포함된 원문 고지 사본입니다. `scripts/supply_chain.py`로 재생성합니다. 직접·간접 의존성을 포함하되 OS 이미지·브라우저·개발 도구와 바이너리 내부에 묶인 모든 C 라이브러리까지 완전 식별한 SBOM은 아닙니다.

- FastAPI/Stripe/Pydantic 등은 MIT, Starlette/Uvicorn/Authlib/HTTPX 등은 BSD 계열입니다. 해당 저작권·허락·면책 고지를 보존해야 합니다.
- `psycopg` 및 `psycopg-binary` 3.3.6 메타데이터는 LGPL-3.0-only입니다. 상업 이용 자체를 일괄 금지하는 라이선스는 아니지만, 라이브러리 사본을 설치본/컨테이너와 전달하면 소스 제공 방식·라이선스·교체/수정 권리 등의 조건 검토가 필요합니다. 일반 상용 EULA로 해당 권리를 막아서는 안 됩니다. 이 저장소의 고지 사본만으로 모든 바이너리 배포 의무가 끝났다고 주장하지 않습니다. 정확한 배포 버전의 소스/빌드 의존성·원문 GPL/LGPL을 제공하는 절차를 먼저 갖추세요. Psycopg 2의 별도 예외를 Psycopg 3에 그대로 적용하지 마세요. [Psycopg 3 저장소](https://github.com/psycopg/psycopg), [GNU 재배포 FAQ](https://www.gnu.org/licenses/gpl-faq.en.html#LGPLStaticVsDynamic)
- `certifi`는 MPL-2.0입니다. 수정 여부와 배포 형태에 따라 해당 코드의 원문/수정분 제공과 소스 취득 안내가 필요합니다. 앱 전체를 자동으로 같은 라이선스로 바꾸라는 뜻은 아닙니다. [Mozilla 공식 FAQ](https://www.mozilla.org/en-US/MPL/2.0/FAQ/)
- cryptography는 Apache-2.0 OR BSD-3-Clause이며 바이너리 내부 구성요소 고지도 포함됩니다. 의존성 설치를 그대로 유지하고 고지를 제거하지 마세요.
- 화면 아이콘은 Lucide ISC와 일부 Feather MIT입니다. `src/netsec/web/assets/LUCIDE-LICENSE.txt`를 유지합니다. 시스템 Arial/Malgun Gothic을 참조할 뿐 폰트 파일을 재배포하지 않습니다.

서버를 직접 운영하는 SaaS와 고객에게 이미지/실행 파일을 전달하는 온프레미스 판매는 검토 범위가 다릅니다. 공개 GitHub에는 앱 소스와 고지·설정 예시를 올리며 의존성 바이너리/비밀/실제 고객 DB는 올리지 않습니다. 고객에게 컨테이너 이미지를 배포하기 전에는 OS·libpq·OpenSSL 등까지 추가 감사하세요. [한국저작권위원회 OLIS](https://www.olis.or.kr/license/introduction.do)

## 고객 로그와 개인정보

이메일·이름·IP·계정 식별자·호스트·인증 기록은 식별 가능성과 처리 맥락에 따라 개인정보 검토 대상입니다. '보안용 로그이므로 동의/근거가 전혀 필요 없다'고 가정하지 않습니다. 운영자의 가입정보 처리와 고객이 맡기는 직원/앱 사용자 로그 처리를 구분하여 처리 근거·목적·최소 항목·접근·보관/파기·정보주체 권리·사고 통지·수탁자/재수탁자 역할을 정해야 합니다.

위탁 시 문서화·수탁자 공개·감독 등에 관한 개인정보 보호법 제26조를 확인하세요. 해외 클라우드/메일/SSO/결제사를 사용하면 제28조의8의 국외 이전 요건과 고지/근거도 검토해야 합니다. '모든 국외 이전에 동일한 동의만 받으면 된다'는 단순 결론을 내리지 않습니다. 약관 확인 체크박스 하나로 모든 직원의 개인정보 처리나 국외 이전 근거를 대신하지 않습니다. [위탁 관련 공식 조문](https://law.go.kr/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1020399009), [국외 이전 공식 조문](https://www.law.go.kr/LSW/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1034292881)

기술 구현은 키/세션 해시, 연결/메일 암호화, 외부 알림 최소화, 보관 정리와 요청 접수를 제공합니다. 디스크/백업 암호화·인력/운영 접근·계약·고지·법정 보존·국외 이전 판단까지 자동 해결한 것은 아닙니다. 삭제 요청 실행 후에도 백업·외부 제공자 기록의 처리와 복구 시 삭제 재적용이 필요합니다.

## 결제·약관·상표·사용 권한

판매자 정보·거래 조건·정기 결제 고지·청약철회/환불·해지 절차·세금/증빙·통신판매 관련 의무를 실제 사업에 맞게 검토하세요. B2B라고 전자상거래법을 언제나 배제하는 것도, 소비자 거래 규정을 모든 기업 계약에 동일 적용하는 것도 부정확합니다. 제3조는 상행위 목적 사업자 거래의 적용 제외와 예외를 규정합니다. [전자상거래법 제3조](https://law.go.kr/LSW/lsLinkCommonInfo.do?lsJoLnkSeq=1027062985)

현재 실제 연결 모듈은 Stripe입니다. 확인한 사업자 지원 국가 목록에 대한민국이 표시되지 않았으므로, 한국 사업자가 키만 발급받아 곧바로 판매할 수 있다고 안내하지 않습니다. 가입 자격과 적합한 국내/해외 PG를 먼저 확인해야 합니다. 결제 모듈의 구현과 PG 계약 성립은 다릅니다. [Stripe 공식 지원 국가](https://stripe.com/global)

NetSec 명칭의 상표·도메인·타사 로고 사용 허락은 조사 완료되지 않았습니다. 타사 제품 인증·파트너·ISMS-P/ISO/SOC2 준수를 표시하지 마세요. 탐지는 검토 단서이며 침해 확정이나 방어 보장이 아닙니다. 자신이 관리하거나 명시적으로 허가받은 서버/앱의 로그와 패킷만 수집하세요. 고객별 수집 권한과 직원 안내도 계약/운영 절차에 남깁니다.
