# 보안 점검 기록

추가 수정: [SSO 취소 경합·오류 응답·공개 웹 보안 헤더 수정과 재검증](SECURITY_FIXES_2026-10-22.md).

후속 조치: [2026-10-22 certifi 보안 업데이트와 재검증](SECURITY_UPDATE_2026-10-22.md). 아래 2026-10-11 결과는 당시의 기록이며 현재 의존성 감사 결과로 해석하지 마세요.

검토일: 2026-10-11. 대상: 0.4.0 SaaS 확장과 기존 모니터링 경계. 코드 검토, 회귀 테스트, 로컬 브라우저 검사, 런타임 의존성 감사와 정적 분석을 수행했습니다. 독립 침투 테스트, 인증 심사, 무취약점 보증은 아닙니다. 실제 실행 결과는 `SAAS_VERIFICATION.md`를 참고하세요.

## 확인한 보호 장치

- 조직은 세션 또는 수집 키에서 결정합니다. 사용자 입력 조직 ID로 다른 고객의 사건/결제/내보내기를 조회하지 못하도록 검사합니다. admin/analyst/viewer 권한을 서버에서 적용합니다.
- 비밀번호는 scrypt, 세션/수집/복구 토큰은 해시로 저장합니다. 복구/초대/확인은 만료와 단일 사용을 적용합니다. 비밀번호 변경/복구/계정 비활성화 시 세션을 폐기합니다.
- 변경 API는 정확한 Origin, JSON, CSRF를 요구합니다. HTTPS 쿠키는 Secure/HttpOnly/SameSite입니다. CSP, 프레임 차단, no-store를 적용합니다. 프록시 주소는 지정된 게이트웨이만 신뢰합니다.
- 가입/로그인/복구/초대/수집/민감한 재인증을 제한합니다. 요청은 1MB, 수집 배치는 200개로 제한합니다. 월별 한도와 중복 제거는 같은 쓰기 트랜잭션으로 처리합니다.
- 이메일 확인 전 로그인을 막습니다. SSO는 Authlib 기반 코드 흐름, PKCE, 서버 state, 브라우저 쿠키, nonce와 토큰 서명/issuer/audience/만료를 검사합니다. 확인된 활성 초대 계정만 연결하고 기본 MFA 증거를 요구합니다.
- 카드 번호를 앱에서 받거나 보관하지 않습니다. Stripe 웹훅은 원문 서명/시각/환경/중복을 검사하고 제공자 현재 상태와 등록된 고객/요청/구독/가격을 대조합니다. 성공 페이지 방문만으로 권한을 지급하지 않습니다.
- 조직별 연결 비밀과 메일의 일회용 링크는 Fernet 인증 암호화로 저장합니다. 복호화 시 조직 일치도 검사하고 읽기 API는 비밀을 반환하지 않습니다. 외부 알림에는 원본 IP/계정/근거를 넣지 않습니다.
- 범용 웹훅은 승인된 HTTPS 443 호스트만 허용하며 공개 IP 확인 후 주소를 고정해 TLS 연결합니다. 리디렉션/사설 주소/환경 프록시는 차단합니다.
- 작업은 lease/재시도/heartbeat를 갖습니다. 삭제는 재인증된 요청과 운영자 확인을 분리하고 다른 조직 데이터가 남는지 검사합니다.

## 점검 중 보완한 항목

- SSO 필수 전환/발급자 변경 시 기존 비밀번호 세션과 미완료 SSO 요청을 폐기합니다.
- 서명 토큰의 nonce/issuer/확인 이메일을 명시적으로 재확인합니다. 단일 하드웨어 인증 방법만으로 MFA라고 판단하지 않습니다.
- 비밀번호 변경 및 운영자 초기화 후 미사용 복구 링크도 폐기합니다.
- 구독/개인정보/연결 설정의 재인증에는 공통 사용자별 제한을 적용하여 경로를 바꾼 반복 시도를 막습니다.
- 최신 Stripe SDK 객체를 구조화된 dict로 변환하고, 상태 재조회와 적용을 직렬화해 오래된 이벤트가 뒤늦게 덮어쓰는 것을 방지합니다.
- PostgreSQL 쓰기는 advisory lock으로 한도/중복/작업 점유의 원자성을 유지합니다. 처리량을 위해 해제하면 동시성 계약을 다시 설계·검증해야 합니다.

## 자동 분석 결과와 해석

`requirements-runtime.lock`의 31개 런타임 버전을 pip-audit로 조회했을 때 알려진 취약점은 발견되지 않았습니다. 이는 조회 시점 데이터베이스에 알려진 항목만 검사한 결과이며 새 취약점이나 OS/바이너리 전체의 안전성을 보증하지 않습니다.

Bandit 전체 경고는 19개입니다: 중간 위험 15개(B608), 낮은 위험 4개(B404/B603), 높은 위험 0개. 경고를 숨기는 `nosec`는 추가하지 않았습니다. CI는 높은 위험/높은 확신 항목을 차단하고 전체 경고를 아티팩트로 보존합니다.

- B608: `dependencies.scoped`의 고정 테이블 허용 목록, `routes_admin`의 고정 업데이트 열, `routes_ops`의 서버가 구성한 필터, `operations`의 고정 내보내기/삭제 목록, `migration`의 고정 TABLES와 검증된 열 식별자입니다. 사용자 값은 바인딩 매개변수로 전달됩니다. 검토한 경로에서 임의 SQL 삽입을 확인하지 못했습니다. 허용 목록을 사용자 입력으로 바꾸면 이 판단은 무효입니다.
- B404/B603: 운영자 전용 pg_dump/pg_restore 호출입니다. shell 문자열 실행을 사용하지 않고 DB 비밀번호는 인자가 아닌 자식 환경에 전달합니다. 실행 파일은 운영자의 PATH에서 절대 경로로 확인한 뒤 실행하므로 PATH/호스트/도구 공급망이 신뢰되어야 합니다. 실패·시간 초과·무효 아카이브는 새로 만든 부분 백업을 제거하며 기존 파일은 덮어쓰지 않습니다. 자식 환경은 같은 권한의 호스트 관리자에게 비밀 저장소가 아닙니다.

## 실제 고객 도입 전 남은 위험

1. 외부 보안 전문가의 침투 테스트, 의존성/OS 이미지 재검사, 부하·동시성·장애/복구 시험이 필요합니다. DDoS/WAF/전역 연결 제한과 모니터링은 인프라 영역입니다.
2. IdP discovery/token/JWKS는 승인 운영자와 제공자를 신뢰합니다. DNS/메타데이터 침해에 대한 완전한 네트워크 격리는 제공하지 않습니다. 이그레스 정책과 실제 IdP MFA/퇴사자 차단 절차가 필요합니다. 로컬 비밀번호 자체의 TOTP/WebAuthn, SCIM/백채널 로그아웃은 미구현입니다.
3. 암호화 키 자동 회전/KMS, PostgreSQL RLS/고객별 DB, 외부 불변 감사 저장소는 없습니다. DB/서버 관리자에게 접근 가능하므로 최소 권한·접근 기록·디스크/백업 암호화·운영자 MFA가 필요합니다. Windows 로컬 키는 NTFS ACL도 별도 설정하세요.
4. 실제 SMTP/IdP/Stripe 계정, 갱신/연체/환불과 실패 복구는 운영자 키를 넣은 별도 스테이징에서 검증해야 합니다. 자동 환불/만료 checkout 정리는 아직 없습니다. HTTPS 환경에서는 로컬 메일/mock/SQLite/빈 암호화 키/미확정 약관 설정으로 시작하지 못하도록 차단합니다.
5. 글로벌 DB 쓰기 lock과 외부 제공자 조회는 지연/가용성 한계가 있습니다. 요금제 한도를 성능 보증으로 광고하지 마세요. 고가용성/다중 리전 운영은 검증하지 않았습니다.
6. 현 DB 삭제는 백업·외부 제공자·에이전트 큐를 지우지 않습니다. 별도 파기와 복원 시 삭제 재적용 절차가 필요합니다. 개인정보·라이선스 쟁점은 `LEGAL_REVIEW.md`에서 별도로 다룹니다.

보안 관련 민감한 제보에는 고객 원본 로그/비밀을 공개 이슈에 올리지 마세요. 실제 서비스 공개 전 비공개 제보 연락처와 사고 대응 담당자를 정해야 합니다.
