# SaaS 확장 사용과 직접 해야 할 일

## 지금 실행

Windows에서 저장소의 `Start-NetSec-SaaS.cmd`를 실행합니다. Python 3.11 이상과 최초 의존성 설치용 인터넷 연결이 필요합니다. 기본 주소는 http://127.0.0.1:8892 입니다. 포트가 사용 중이면 다음 빈 포트를 선택하고 터미널에 주소를 표시합니다. 실행 창을 닫으면 서비스가 종료됩니다.

기존 `Start-NetSec.cmd`의 8890 운영 앱과 DB를 바꾸지 않습니다. SaaS 실행기는 별도 `data-saas`와 `.netsec-key`를 사용하고 로컬 메일·테스트 결제를 강제합니다. 이 실행기는 `.env`를 읽지 않는 개발용입니다. 실제 개인정보나 운영 로그를 넣지 마세요. 같은 PC 사용자는 로컬 테스트 메일에 접근할 수 있습니다.

1. 회사 계정 만들기에서 회사·관리자·이메일·비밀번호를 입력하고 개발용 약관 안내를 확인합니다.
2. 로컬 테스트 메일에서 링크를 열고 이메일 확인을 완료합니다. 메일에 조직 ID가 있습니다.
3. 조직 ID·이메일·비밀번호로 로그인합니다.
4. 구독·사용량에서 요금제를 선택하고 테스트 결제를 확인합니다. 실제 청구는 없습니다.
5. 연결 소스에서 수집 키를 만들고 합성 이벤트를 보내거나 기존 SDK/에이전트를 연결합니다.
6. 사용자는 이메일 초대로 추가합니다. 수집·처리 상태, 사건 기한, 외부 연결, 데이터 관리를 사용할 수 있습니다.

POSIX 수동 실행:

```sh
python -m pip install '.[packets,monitor,saas,test]' -c requirements-runtime.lock
NETSEC_SAAS_ENABLED=1 NETSEC_DB=data-saas/netsec.sqlite3 NETSEC_ORIGIN=http://127.0.0.1:8892 python run.py monitor --port 8892
```

## 코드로 준비한 범위

- 이메일 확인 가입·초대/취소·계정 복구, 서버 저장 단일 사용 토큰.
- 14일 체험, Starter/Team/Business 수집량·좌석·소스·보관 한도. 가격 자체는 판매자가 정합니다.
- mock 결제와 선택적 Stripe hosted checkout/포털/기간 종료 해지, 서명·재전송 방지·현재 상태 재조회.
- 조직별 암호화 연결 설정, OIDC/PKCE/nonce 기반 SSO와 MFA 증거 정책.
- 수집 지연/처리기 상태, 추가 인증 탐지, 기한·외부 티켓 참조·재알림.
- 고객 데이터 내보내기·삭제 요청과 운영자 삭제 명령.
- PostgreSQL 지원, SQLite 스냅샷 이전, 별도 작업 처리기, 백업과 별도 DB 복원 검사, TLS 게이트웨이 컨테이너 구성.

## 실제 판매 전에 직접 할 일

1. 사업자·판매 지역·고객 범위·가격·세금/증빙·해지/환불 조건을 확정합니다. 약관·개인정보 처리방침·고객 로그 처리위탁 계약을 법률 전문가와 검토합니다. NetSec 이름의 상표 권리는 확인되지 않았습니다.
2. 프로젝트 원본 코드의 라이선스 정책을 결정합니다. 공개 저장소라는 사실만으로 MIT 등의 허용이 생기지 않습니다. LGPL/MPL 의존성의 배포 조건은 `LEGAL_REVIEW.md`를 따릅니다.
3. 서버·도메인·TLS·PostgreSQL·암호화 저장소·백업·제한된 운영 계정을 준비합니다. `.env.example`의 키 항목은 비워 두었습니다. 암호화 키를 별도 비밀 저장소에서 생성·보관하고 DB 백업과 함께 복구 가능하도록 관리합니다.
4. 메일 제공자와 회사 OIDC 앱을 등록합니다. SMTP 수신, OIDC 발급자/대상/PKCE/nonce/MFA 클레임을 실제 계정으로 검증합니다. 웹훅은 운영자가 허용한 공개 HTTPS 호스트만 연결합니다.
5. 결제 제공자 가입 자격부터 확인합니다. 제공된 실제 연결 모듈은 Stripe이며 한국 사업자의 가입 가능성을 가정하지 않습니다. 국내 PG 연결은 미구현입니다. PG 등록이 불가하면 `off` 상태로 유지하고 적합한 제공자 어댑터를 추가해야 합니다. 외부 키를 넣는 것만으로 국내 결제가 완성되는 것은 아닙니다.
6. 실제 테스트 결제·실패·갱신·순서 역전·해지·환불·중복 청구 방지를 제공자 환경에서 검증하고, 독립 침투 테스트·부하/복구 훈련을 진행합니다. 이 저장소가 보안 인증이나 무결점 보증을 제공하지는 않습니다.

HTTPS SaaS는 로컬 메일/mock 결제/SQLite/빈 암호화 키/미검토 문서 설정을 거부합니다. 준비 후 `NETSEC_MAIL_MODE=smtp`, `NETSEC_BILLING_MODE=off` 또는 `stripe`, 실제 문서 URL과 버전을 넣고 검토자가 `NETSEC_LAUNCH_CONFIRMED=1`로 명시해야 합니다. 이 플래그는 법적 검토를 대신하지 않습니다.

실서비스 배포는 실행기를 사용하지 않고 `SAAS_OPERATIONS.md`의 절차를 따릅니다. GitHub 업로드와 인터넷 서비스 배포는 서로 다른 작업입니다.
