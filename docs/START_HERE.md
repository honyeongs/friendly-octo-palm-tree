# 처음 사용하기

## 지금 바로 사용할 때

1. Windows에서 저장소의 `Start-NetSec.cmd`를 실행합니다. Python 3.11 이상과 첫 설치 시 인터넷이 필요합니다. 실행 창을 열어 둡니다.
2. 브라우저에서 http://127.0.0.1:8890 을 엽니다.
3. 첫 화면에서 조직 이름, 관리자 이름, 이메일, 12자 이상 비밀번호를 직접 정합니다. 외부 계정이나 API 키는 필요 없습니다.
4. 연결 소스에서 앱 또는 SSH 소스를 추가합니다. 수집 키는 한 번만 표시되므로 비밀 저장소에 보관합니다. 분실하면 기존 키를 폐기하고 새 소스를 만듭니다.
5. 앱 소스를 만들 때 표시되는 `합성 인증 이벤트 6개 보내기`로 사건 생성과 처리 흐름을 확인할 수 있습니다. 이 버튼은 실제 공격을 일으키지 않습니다.

화면의 조직 ID는 로그인에 필요합니다. 현재 브라우저에는 조직 ID만 저장하며 비밀번호와 수집 키는 저장하지 않습니다. 새 브라우저에서는 동일한 조직 ID를 입력합니다. 관리자는 사용자 메뉴에서 분석가·조회자를 추가할 수 있습니다.

기존 오프라인 분석 명령과 보고서 비교 화면도 그대로 유지됩니다. 운영 화면 왼쪽의 기존 보고서 비교를 열거나 `python run.py serve`를 실행합니다.

## 직접 해야 할 것

- **필수:** 관리자 계정 정보 정하기, 자신의 앱·서버에 수집 키 연결하기.
- **이메일 알림을 쓸 때만:** `.env.example`을 `.env`로 복제한 뒤 SMTP 호스트·계정·비밀번호·발신 주소를 입력하고 서버를 재시작합니다. 화면의 정책·예외에서 수신 이메일도 지정합니다.
- **웹훅 알림을 쓸 때만:** `.env`의 HTTPS 웹훅 주소와 필요한 토큰을 입력하고 서버를 재시작합니다. 조직의 정책·예외에서 웹훅을 활성화합니다. 범용 JSON 웹훅이므로 Slack 등 특정 서비스는 해당 서비스용 중계/변환기가 필요할 수 있습니다.
- **회사에 배포할 때만:** 서버·도메인·HTTPS 인증서·방화벽을 준비하고 [운영 가이드](MONITOR_OPERATIONS.md)의 배포 절차를 수행합니다. 이 저장소는 공개 인터넷에 자동 배포되지 않습니다.

SMTP·웹훅 항목은 모두 비워 두었습니다. 비워도 수집·분석·사건 처리·화면 알림은 정상 동작합니다. 메일 발송과 외부 웹훅 도착 여부는 실제 설정을 넣은 뒤 확인해야 합니다.

## 실제 샘플 앱 연결

앱 소스의 키를 준비하고 저장소에서 새 PowerShell 창을 엽니다.

```powershell
$env:NETSEC_SOURCE_KEY = '화면에서 생성한 앱 수집 키'
.\.venv\Scripts\python.exe run.py demo-app
```

http://127.0.0.1:8891 에서 샘플 계정을 직접 만듭니다. 같은 아이디에 틀린 비밀번호를 5번 입력한 뒤 60초 안에 올바른 비밀번호로 로그인하면 운영 화면에서 관련 사건을 확인할 수 있습니다. 운영 화면은 약 15초마다 갱신되며 새로 고침도 가능합니다. 샘플 앱은 로컬 기능 검증용이며 실제 서비스의 인증 서버로 사용하지 않습니다.

자신의 Python 앱에는 [연결 가이드](APP_INTEGRATION.md)의 SDK를 사용합니다. SDK는 외부 키 없이 자체 수집 키만 필요합니다.

## 다시 실행·종료

실행 창에서 Ctrl+C로 종료하고 `Start-NetSec.cmd`로 다시 시작합니다. 계정·사건·메모는 `data/netsec.sqlite3`에 남습니다. `data`를 지우면 기록도 사라집니다. 실제 데이터와 `.env`는 Git에 올리지 않도록 제외했습니다.

이메일 인증, SSO/MFA, 고가용성, 법적 준수 인증은 포함되지 않습니다. 현재 버전은 제한된 환경의 시범 운영용입니다.
