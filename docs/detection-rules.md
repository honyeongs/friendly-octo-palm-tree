# SSH 반복 인증 실패 탐지 규칙

## 입력 형식

UTF-8 또는 UTF-8 BOM 파일을 읽는다. 한 줄은 `ISO시각 호스트 sshd[PID]: 인증메시지` 형식이다. PID 없는 sshd 및 sshd-session도 지원한다. ISO 시각은 UTC 오프셋 또는 Z가 필수다.

지원 인증 메시지는 아래와 같다. 인증 방식은 password, publickey, keyboard-interactive/pam 중 하나이다. ssh2 뒤의 공개키 지문 등 추가 텍스트는 허용한다.

```text
2026-10-11T10:00:00+09:00 lab sshd[123]: Failed password for alice from 192.0.2.10 port 50001 ssh2
2026-10-11T10:00:01+09:00 lab sshd[123]: Failed password for invalid user admin from 192.0.2.10 port 50001 ssh2
2026-10-11T10:00:02+09:00 lab sshd[123]: Accepted publickey for alice from 2001:db8::10 port 50001 ssh2 ED25519 SHA256:synthetic
```

포트는 1~65535이고 IP 주소를 검증한다. IPv6는 표준 축약 표현으로 통일한다. 인터페이스 범위가 붙은 IPv6는 지원하지 않는다. 호스트 이름은 입력 문자열 그대로 구분하므로 같은 서버의 별칭을 자동으로 합치지 않는다.

전통적인 `Oct 11 10:00:00 ...` 로그는 연도와 시간대를 자동 추정하지 않는다. RFC 5424 전체 메시지, 압축 파일, 타임스탬프 없는 로그는 지원하지 않는다. OpenSSH 공개키 지문 앞의 `ssh2:` 표기도 지원한다.

Linux journal 입력은 journalctl -o json의 한 줄당 JSON 객체를 읽는다. __REALTIME_TIMESTAMP의 마이크로초 문자열, _HOSTNAME, SYSLOG_IDENTIFIER(없으면 _COMM), MESSAGE를 사용한다. 식별자는 sshd 또는 sshd-session이어야 한다. 다른 서비스는 제외하며 이진 MESSAGE, 잘못된 시각·호스트는 손상된 줄로 계산한다. 자동 감지는 첫 번째 비어 있지 않은 줄이 `{`로 시작하면 journal 형식을 선택한다. --format으로 명시할 수도 있다.

## 통계 해석

- total_lines: 입력 줄 전체 수
- blank_lines: 빈 줄 수
- ignored_lines: 관련 없는 줄 또는 지원하지 않는 이벤트 형식
- malformed_lines / malformed_line_numbers: 지원 인증 메시지로 보이지만 시각·IP·포트·구조가 잘못된 줄의 수와 번호
- parsed_events: 유효한 인증 이벤트 수
- failed_events / accepted_events: 유효한 실패/성공 수
- finding_count: 병합 후 의심 구간 수

항상 `total_lines = blank_lines + ignored_lines + malformed_lines + parsed_events`이다. 손상된 인증 줄이 있으면 표준 오류에 경고한다. 지원 이벤트가 0개면 분석 불가 오류로 종료하며 보고서를 생성하지 않는다.

## 이동 시간 구간

대상 호스트와 출발지 IP가 같은 실패 이벤트만 모은다. 시각순으로 정렬하고, 동일 시각에서는 원본 줄 번호순으로 정렬한다. 각 실패 시각 t에서 `[t - window_seconds, t]` 안의 실패를 세어 threshold 이상이면 탐지한다.

window_seconds는 1~86400의 정수이며 기본 60이다. threshold는 1 이상의 정수이며 기본 5이다. 사용자 이름은 그룹 키가 아니므로 같은 IP에서 여러 계정을 시도하면 함께 계산된다. 서로 다른 서버의 실패는 합치지 않는다.

성공 이벤트는 실패 수에 들어가지 않으며, 실패 누적을 초기화하지 않는다. 중복 입력 줄은 각각 계산한다. 로그 전달 경로에서 중복된 경우 실패 수가 실제보다 커질 수 있다.

## 구간 병합과 근거

각 탐지의 근거 시간 구간이 겹치거나 맞닿으면 하나로 병합한다. 실패 근거는 원본 줄 번호 기준으로 중복 없이 보관한다. 보고서의 failure_count는 병합 구간 전체 실패 수이고 peak_window_failures는 한 이동 시간 구간에서 관측한 최대 실패 수이다. 병합 구간은 window_seconds보다 길어질 수 있다.

예를 들어 0, 10, 20, 30, 40, 50, 60, 70초에 같은 IP의 실패가 발생하면, 기본값에서 의심 구간은 1개, 전체 실패는 8회, 60초 이동 구간의 최대 실패는 7회이다.

근거는 UTC 시각, 입력 줄 번호, 사용자, 인증 방식, 출발지 포트, invalid user 여부를 포함한다. 현재 결과는 schema_version 1.1의 JSON이다. 기존 findings 형식을 유지하며 success_after_failures와 선택적인 network를 추가한다. 웹 화면은 기존 1.0 결과도 읽는다. 실행 시각을 넣지 않으므로 같은 파일·옵션의 출력은 동일하다. source는 입력 파일명만 기록한다.

## 실패 후 성공 상관분석

호스트·IP·사용자별로 시각순 분석한다. 사용자별 이동 구간에 실패가 threshold 이상 있었고, 그 구간 마지막 실패 후 success_window_seconds 안에 첫 성공이 있으면 상관분석 결과를 만든다. 기본값은 300초, 양 끝을 포함한다. 같은 시각이면 원본 줄 순서를 사용한다. 성공이 먼저 있거나 사용자가 다르면 연결하지 않는다.

성공이 발생하면 해당 사용자 그룹의 실패 이력을 초기화한다. 임계값에 못 미치는 나중의 고립된 실패가 이전 의심 구간의 유효 시간을 연장하지 않는다. 전체 IP의 반복 실패 규칙과 달리 사용자별 임계값을 만족해야 한다. 결과에는 실패 줄 번호, 성공 줄 번호·시각·방식, 마지막 실패에서 성공까지의 시간 차이가 포함된다.

## TCP 관측 연결

dpkt 1.9.8을 선택 의존성으로 사용한다. 하나의 section/interface에 속한 시각 있는 PCAP/PCAPNG를 지원한다. Ethernet, RAW IP, Linux cooked v1/v2, loopback 링크를 읽고 IPv4/IPv6 TCP를 분석한다. IPv4 단편은 분석에서 제외한다. 다중 인터페이스 PCAPNG는 잘못된 시간·링크 해석을 피하기 위해 거부한다.

명시한 서버 IP와 포트에 대해 클라이언트 SYN, 서버 SYN-ACK, 양방향 RST를 집계한다. 같은 클라이언트 IP·포트·초기 순서 번호의 SYN은 같은 시도에 대한 재전송으로 센다. 시도 수는 TCP 연결 성공이나 SSH 인증 시도 수와 동일한 뜻이 아니다.

로그 호스트와 서버 IP를 대응시키고 각 SSH 의심 구간의 시작·종료에 기본 5초 여유를 둔다. 그 시간 범위 안에서 같은 클라이언트 IP의 TCP 근거를 연결한다. 여러 로그 호스트는 --server-host를 명시해야 한다. 서버 주소나 캡처 시각이 맞지 않으면 matched=false가 된다. 캡처된 응답 누락을 연결 실패로 단정하지 않는다.

## 한계와 해석

반복 실패는 징후이며, 공격 또는 침입 성공을 확정하지 않는다. 사용자 실수, 공유 출발지 IP, 잘못된 자동화 자격증명으로 오탐할 수 있다. 여러 IP로 분산하거나 임계값 아래에서 천천히 시도하면 놓칠 수 있다.

첫 버전은 이벤트 전체를 메모리에 올려 정렬한다. 시간 복잡도는 정렬을 포함해 O(n log n), 메모리는 O(n)이며 대규모 운영 로그용 스트리밍 엔진은 아니다. 파일 시각의 정확도, 호스트 이름의 일관성, 누락 로그는 입력에 의존한다.

실제 운영 로그에는 사용자와 IP가 포함될 수 있다. 공개 예시에는 samples/ssh의 합성 데이터를 사용하며 원본 운영 로그를 저장소에 올리지 않는다.
